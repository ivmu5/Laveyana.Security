## Дополнительные исправления по результатам реальной компиляции (2026-10-16)

- `CS9108` ранее исправлен в `SoftwareKeyReprotectionService`: `ReadOnlySpan<byte>` больше не захватывается вложенной лямбдой; временная копия очищается в `finally`. Исправление уже содержалось в полученном архиве.
- `CS0618` в `KeyLifecycleTests`: заменён устаревший делегат NUnit `TestDelegate` на `Action` без изменения проверки ожидаемого исключения.
- `CS9174` в `SoftwareKeyReprotectionTests`: литерал коллекции заменён явным `byte[]` для параметра `ReadOnlyMemory<byte>`.
- `CS1591` в тестовых проектах: отключена генерация XML-документации **только** для двух тестовых сборок. Документирование публичного API пяти продуктовых проектов остаётся обязательным; NUnit-тесты не являются публикуемой API-библиотекой.

**Важно:** это исправления исходников на основании полученного списка диагностик. Без .NET SDK в окружении проверки невозможно утверждать, что решение полностью компилируется или проходит NUnit. ## Работа с уже распакованным проектом

Не накладывайте новую версию ZIP поверх старых файлов: удалённый `SoftwareKeyExceptions.cs` иначе останется рядом с новыми файлами исключений, вызывая дублирующиеся типы. Сделайте резервную копию старой папки, распакуйте новую версию в **чистую папку**, перенесите свои настоящие `packages.lock.json` из резервной копии (если они созданы NuGet) в соответствующие каталоги. Итоговый архив сохраняет настоящие lock-файлы, предоставленные пользователем, и не содержит созданных вручную lock-файлов.

Затем откройте решение и выполните **Release → Сборка → Пересобрать решение**. Если появятся новые ошибки компиляции, сохраните полный список и журнал `Вывод → Сборка` для следующего исправления. Не скрывайте ошибки отключением анализаторов.

Остальные проблемы безопасности из Phase 27 остаются открытыми: Windows TOCTOU, rollback snapshots, nonce lifetime, обязательная платформенная приёмка.
