# Laveyana.Security — экспериментальное использование и известные ограничения

[English](Laveyana.Security.KnownLimitations.md) | **Русский**

**Дата статуса:** 21 октября 2026 года  
**Стадия:** до релиза (`1.2610.0-alpha.1`); **допуск Phase 27 к production: NO-GO**.

Этот документ устанавливает текущие правила использования библиотеки **до** закрытия всех этапов приёмки безопасности. Здесь перечислены допустимые сценарии и гарантии, которые *не подтверждены*. Документ **не** означает допуска к защите production-секретов, не сертифицирует приложение и не заменяет подробный [аудит Phase 27](Laveyana.Security.Phase27.SecurityAudit.ru.md). Результаты проверки приложенного ZIP нельзя автоматически переносить на другую ревизию Git.

## Что можно использовать сейчас

| Область | Рекомендация |
| --- | --- |
| Криптографические примитивы в памяти, контракты и композиция провайдеров | Допустимы **для разработки, тестов и контролируемого внутреннего применения** при отдельной проверке криптографического протокола и обработки ошибок приложения. Тесты библиотеки не доказывают безопасность протокола приложения. |
| Операции с временными программными ключами | Использовать с воспроизводимыми тестовыми данными и явным владением материалом. Соблюдать ограничения срока жизни AEAD nonce ниже. |
| `Laveyana.Security.FileSystem` | **EXPERIMENTAL / TEST ONLY.** Для обычной записи требуется явное `EnableExperimentalWrites`; использовать только изолированные, заменяемые тестовые хранилища, а не реальные production-секреты или единственные копии ценных ключей. |
| Windows DPAPI CurrentUser protector | Компонент привязан к Windows и профилю пользователя; выбор DPAPI **не** превращает экспериментальное файловое хранилище в production-решение. |
| Сохранение с защитой от rollback, защищённые файловые записи и хранение боевых ключей | **Не допущены.** Если приложению такие гарантии нужны уже сейчас, следует выбрать отдельно проверенное хранилище или провайдер. |

## Открытые замечания и существенные ограничения

| ID / область | Статус | Что важно при использовании |
| --- | --- | --- |
| **SA-03 — rollback / replay снимков** | **OPEN** | Аутентификация снимка не обнаруживает подмену ранее корректной версией. Есть необязательные контракты внешнего rollback-authority и режим проверки только для чтения, но отсутствуют законченный устойчивый протокол защищённой записи/восстановления, защита от отключения проверки (downgrade) и встроенный независимый authority. `ProvidesRollbackProtection=false`. |
| **SA-04 — срок жизни AEAD nonce** | **OPEN** | Randomized AES-GCM в software backend допустим для ключевого материала, созданного **тем же экземпляром** `SoftwareKeyProviderBackend`, с лимитом `2^20` выданных nonce на материал. Перезапуск, импорт, повторное открытие, восстановление или клонирование памяти не создают новый безопасный срок жизни для шифрования; нужен новый ключевой материал. Историческое расшифрование — отдельный сценарий. Встроенный backend отклоняет deterministic nonce allocators. |
| **SA-08 — долговечность хранилища / испытания отказов** | **OPEN** | Завершение процесса и fault injection **не эквивалентны** реальному отключению питания. Linux `fsync(file)` и `fsync(directory)` проверялись на контейнерной overlay-ФС, а не на квалифицированной цепочке физического хранения. Для Windows не доказан барьер долговечности имени после rename. Испытания с жёстким отключением VM и физическим обесточиванием **не проводились**. |
| **SA-02 — подмена пути / TOCTOU** | **CLOSED, ограниченно** | Операции относительно дескриптора каталога и набор регрессионных тестов Windows/Linux позволили ограниченно закрыть инженерное замечание. Это не гарантия против всех гонок, ошибок ACL/конфигурации или особенностей ФС. SA-08 остаётся открытой. |
| **Observability / аудит** | **Best-effort, не транзакционный** | Необязательный sink вызывается асинхронно с ограничением одновременных вызовов. События могут пропадать, приходить не по порядку или теряться при завершении процесса. Это не постоянный журнал аудита для compliance. |
| **Жизненный цикл и обработка отказов** | **Ответственность приложения** | Отмена после возможной публикации не означает гарантированный откат. При неопределённом результате commit требуется проверка/согласование состояния, **а не** автоматический повтор. Резервное копирование и координация независимых процессов остаются внешними задачами. |
| **Функциональность** | **Не реализована** | Отсутствуют публичный HPKE `Seal/Open`, AEAD-шифрование потоков, универсальный постоянный исполнитель асимметричных приватных ключей и встроенный постоянный generic-secret backend. |
| **Распространение** | **До релиза** | Сборки ориентированы на `net10.0`; `IsPackable=false`; публичный NuGet-пакет и обещание стабильности API отсутствуют. Для первых интеграций применять явные ProjectReference с фиксацией ревизии. |

## Что действительно подтверждено

- **H01 (16 октября):** обязательные Release CI-проверки Windows/Ubuntu и первый ручной многократный регрессионный прогон завершились успешно. Это подтверждение инфраструктуры разработки, **не** сертификация безопасности.
- **SA-08 (21 октября), исполняемый аудит Linux:** отдельный приложенный экспорт успешно собрался; пройдены **334 unit-теста** и **126 интеграционных тестов**, ещё **41 интеграционный результат — `NotExecuted`** (преимущественно Windows-сценарии). Дополнительные тесты аварийного завершения процесса и внедрённой ошибки пройдены на Ubuntu container overlayfs. Windows, жёсткое отключение VM и физическое обесточивание **для этого экспорта не проверялись**.
- В другом отчёте SA-08 среда не позволила запустить .NET; выполнялись только Python/native-пробы. Эти отчёты имеют разную глубину проверки: нельзя суммировать их в утверждение о полной кроссплатформенной долговечности.
- Нового воспроизведённого повреждения снимка упомянутые Linux-пробы не выявили. **Отсутствие воспроизведения не доказывает отсутствие уязвимостей.**

## Минимальные условия использования сейчас

1. Начать с внутреннего/тестового приложения и **некритичных либо воспроизводимых данных**, предпочтительно с ключами в памяти или заменяемыми тестовыми ключами. Не переносить невосполнимые секреты в экспериментальное хранилище.
2. Зафиксировать конкретную ревизию зависимости и явно настроить provider, protector и store. `AddSecurityDefaults` не создаёт защищённое хранилище автоматически.
3. Учитывать владение памятью, лимиты nonce, авторизацию, отмену и ошибки конкретного API. При необходимости очищать секретные массивы, принадлежащие вызывающему коду.
4. Сохранить быстрые обязательные проверки Pull Request в CI; **ради начала пилотного использования не требуется заново выполнять расширенный регрессионный прогон**. Интеграционные сценарии проверять по мере их добавления.
5. **До** перехода к реальным production-секретам или боевому файловому хранению отдельно пересмотреть открытые замечания и собрать доказательства для конкретной среды исполнения.

**Решение:** **ПИЛОТНОЕ / ВНУТРЕННЕЕ ИСПОЛЬЗОВАНИЕ — ДА, в указанных границах. PRODUCTION SECURITY ACCEPTANCE — НЕТ.** SA-03, SA-04 и SA-08 открыты; Phase 27 остаётся NO-GO до самостоятельной приёмки.
