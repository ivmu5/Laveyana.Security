# Laveyana.Security LibraryWorkbench

**Внутренняя лаборатория** для изучения текущих исходников Laveyana.Security. Не предназначена для распространения, хранения реальных секретов и оценки production-безопасности. Phase 27: `NO-GO`; SA-03 и SA-04 ещё открыты.

## Открытие и запуск

1. Создай Git-ветку `tools/library-workbench` от актуального `master`.
2. Распакуй архив **в корень репозитория**. Папка `tools/LibraryWorkbench/` должна оказаться рядом с `src/`, `tests/`, `docs/`.
3. В Visual Studio 2022 с поддержкой .NET 10 и WPF открой `tools/LibraryWorkbench/Laveyana.Security.LibraryWorkbench.sln`.
4. Восстанови NuGet-зависимости, выбери **Debug**, назначь `Laveyana.Security.App.LibraryWorkbench` запускаемым проектом.
5. Нажми **F5**. Worker собирается автоматически и копируется в подпапку `worker/` выходного каталога WPF-проекта.
6. В каталоге найди `LocalCryptography`; открой вкладку **Эксперименты** и вызови SHA-256 или HMAC. Для пошаговой отладки открой `src/Laveyana.Security/Primitives/LocalCryptography.cs`, установи breakpoint, повтори вызов.

> Важно: основное `Laveyana.Security.sln` не изменено. Отдельное Windows-решение не добавляет WPF в Ubuntu CI. Для приложений из `tools/` общие `.props` репозитория продолжают действовать.

## Возможности

- **Reflection**: публичные типы всех пяти основных сборок, сигнатуры методов, зависимости, базовые классы, реализации интерфейсов в просканированных сборках.
- **Сгенерированные формы**: поля `string`, `int`, `double`, `Guid`, `DateTime`, `bool`, `enum`. Сложные типы показываются как неподдерживаемые; выполнение по умолчанию заблокировано.
- **Ручные экраны**: `LocalCryptographyView` заменяет автогенерацию во вкладке экспериментов для этого типа. Обобщённые метаданные и методы остаются доступны отдельно.
- **Безопасные методы**: в автоформе разрешён только `LocalCryptography.GenerateRandomBytes(int)` с лимитом 1–256 байт. Выполнение идёт через типизированный адаптер, без `MethodInfo.Invoke`; содержимое случайных байтов не записывается в журнал.
- **Реальные криптографические демонстрации**: `LocalCryptography.Sha256` и `HmacSha256`/`VerifyHmacSha256`; ключ HMAC генерируется в памяти и очищается после использования.
- **Worker**: отдельный процесс с Named Pipes, тайм-аутом и allowlist. Два сценария: SHA-256 и запись/чтение только синтетического файла в новой папке `%TEMP%` с последующим удалением.
- **Открытие исходника**: по имени типа ищется `.cs` в соответствующей папке `src/` и открывается связанной IDE. Можно выбрать Visual Studio в настройках Windows как приложение для `.cs`.
- **Журнал**: ошибки, время, факт выполнения и состояние без вывода секретных буферов. Экспорт вручную в `.txt`.
- **Настройки**: тема, размер окна и последний тип сохраняются в `%LOCALAPPDATA%/Laveyana/Security/LibraryWorkbench/settings.json`.

## Ограничения первой версии

Это **рабочая лаборатория для изучения**, а не универсальный безопасный исполняющий движок. Reflection не определяет побочные эффекты. Поэтому новые классы видны автоматически, но методы не запускаются, пока не появится зарегистрированный безопасный сценарий. Автогенерация сложных форм, конструкторов с зависимостями и методов с `Span<T>` пока ограничена обзором сигнатур. Worker не является OS-песочницей и работает с правами пользователя.

В текущей версии **не выполняются** настоящие мутации `FileSystemKeyStore`; его API можно изучить и отладить отдельно. Проект не меняет исходники библиотеки и не создаёт демонстрационные секреты на постоянном хранилище.

Для отладки worker запусти сценарий и используй **Debug → Attach to Process** для `Laveyana.Security.App.LibraryWorkbench.Worker.exe`. Worker короткоживущий, поэтому удобно временно добавить breakpoint в `Program.cs` и запустить его под отладчиком; подключение к нему не гарантируется до выхода без предварительной настройки ожидания. Основная отладка через F5 работает непосредственно для in-process-сценариев.

## Где расширять

- `Discovery/TypeCatalog.cs` — список сканируемых сборок.
- `Views/LocalCryptographyView.*` — пример приоритетного ручного UI.
- `MainWindow.xaml.cs` — фабрика редакторов аргументов, можно впоследствии перенести в отдельный модуль.
- `Services/SafeMethodRegistry.cs` — типизированные разрешённые методы и лимиты.
- `Worker/Program.cs` — реестр внешних сценариев с фиксированными именами, без произвольных путей и реальных секретов.
- `Contracts/ScenarioMessages.cs` — формат IPC-запроса/ответа.

## Проверка после установки

- WPF-приложение открывается и позволяет фильтровать каталог.
- `LocalCryptography` показывает пользовательский экран с SHA-256/HMAC.
- Другие классы показывают автоматически сгенерированные сведения и параметры методов; исполнение неизвестных методов отключено.
- Разрешённый `GenerateRandomBytes(32)` выполняется без вывода случайных данных.
- Оба worker-сценария выполняются; `worker/` действительно содержит `*.runtimeconfig.json` и `*.dll`.
- Команда `dotnet test` из корня работает как прежде — WPF не включён в исходное кроссплатформенное решение.

**Статус проверки пакета:** состав и структура проверены статически. Сборка Windows и интерактивная проверка WPF в данной среде не выполнены; установка требует локальной проверки и при необходимости корректировок.
