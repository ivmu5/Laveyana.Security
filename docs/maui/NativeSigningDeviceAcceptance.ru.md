# Матрица аппаратных испытаний NativeKeys (не выполнена)

**Статус:** НЕ ПРОВЕРЕНО на физических устройствах. Компиляция и эмулятор
не означают PASS. Алгоритм: ECDSA NIST P-256 / SHA-256 / подпись P1363 (64 байта).

## Протокол испытания

Для каждой цели (Windows TPM / Android TEE/StrongBox / iOS Secure Enclave /
Mac Catalyst Secure Enclave) запишите модель, OS build, версию .NET,
идентичность приложения и пользователя, аппаратные возможности, дату,
точный commit SHA, постоянный тестовый ProviderId и новый KeyId.
Сохраняйте SHA-256 отпечаток публичного SPKI, **не** приватные данные.
Каждый сценарий отмечайте PASS/FAIL/SKIP с ошибками.

## Обязательные сценарии

1. До создания `FindAsync(keyId)` возвращает null. Сохранить оба ID **до**
   вызова `CreateAsync`.
2. Создать ключ, сверить `ProviderId` и `KeyId`. Экспортируемый публичный
   SPKI должен соответствовать P-256; сам SPKI не является аттестацией.
3. Создать **новый экземпляр** сервиса, открыть тот же ключ и сверить отпечаток.
   Подписать тестовое сообщение с доменным префиксом и проверить подпись
   P1363 публичным ключом. Изменённое сообщение не должно проходить проверку.
   API платформы не должен разрешать экспорт приватного материала.
4. Повторное создание **того же ID** не должно менять публичный ключ.
   Если alias заменяется — FAIL; необходима отдельная сериализация вызовов.
5. Перезапустить **процесс приложения** и повторно открыть/использовать ключ
   по сохранённым ID. Отдельно проверить новый процесс того же пользователя
   там, где это допустимо платформой.
6. Проверить блокировку устройства, отсутствие TPM/TEE/Enclave, отказы
   разрешений и отсутствие автоматического программного fallback.
7. Удалить ключ. Новый экземпляр должен получить null, подпись должна
   завершаться ошибкой. Это не доказательство физического стирания.
8. На одноразовых ключах воспроизвести прерванное создание/удаление и
   конкурентное создание одного ID. Регистрировать неопределённый исход;
   не повторять создание вслепую.
9. Проверить удаление/переустановку приложения и backup/restore.
   Указать реальное поведение устройства.
10. Windows: попробовать подпись в **другом процессе того же пользователя**
    и зафиксировать фактическую ACL/политику доступа. Неэкспортируемость
    ключа не означает эксклюзивность доступа конкретному приложению.

### Windows TPM (ручной запуск)

```powershell
$env:LAVEYANA_RUN_TPM_TESTS = "1"
dotnet test tests/Laveyana.Security.Tests/Laveyana.Security.Tests.csproj -c Release --filter "WindowsTpmRoundTripRequiresExplicitOptIn"
Remove-Item Env:LAVEYANA_RUN_TPM_TESTS
```

Только Windows-ПК с TPM. Тест создаёт постоянный одноразовый ключ; при
аварийном завершении может потребоваться ручная очистка. Не проверяет
новый ОС-процесс, power-loss или аппаратную аттестацию. Данные о
фактическом прохождении аппаратных испытаний отсутствуют.

## Разделение доменов подписи

`SignAsync` подписывает точно переданные байты. Каждый протокол приложения
должен определять **однозначное каноническое сообщение**: домен
(`Laveyana/AppName/Purpose/v1`), длины полей, идентификаторы объекта и
контекста, хеш payload. Нельзя использовать один ключ для неделимых
произвольных сообщений из разных протоколов.

**Решение до испытаний: DEVICE NO-GO.** Независимо от этого SA-03/04/08
по общему persistent-хранилищу остаются OPEN.
