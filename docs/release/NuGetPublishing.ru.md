# Автоматическая публикация предварительных пакетов NuGet

[English](NuGetPublishing.md) | **Русский**

## Что публикуем

Публикуются ровно шесть явно выбранных проектов из `src/`. Нативные Android/Apple проекты, тесты и экспериментальный workbench **не публикуются**. Корневой `Directory.Build.props` оставляет `IsPackable=false`, а шесть проектов явно включают упаковку. Общие метаданные и предупреждающий README задаются в `Directory.Build.targets`.

Обычный CI на PR и в `master` **только создаёт пакеты для проверки, не публикуя их**. Публикация срабатывает **только** при создании GitHub Release с тегом, который в точности соответствует версии в `Directory.Build.props` (например, `v1.2610.0-alpha.1`).

Workflow проверяет, что коммит тега входит в историю `master`, повторяет Release-сборку/тесты, создаёт ровно шесть пакетов и получает NuGet OIDC доступ **только** в защищённом задании публикации. Публикацию одной версии нельзя свободно отменить или заменить; загрузка шести пакетов не атомарна.

## Однократная настройка (владельцем репозитория)

1. Войти на **nuget.org** под учётной записью владельца пакетов. В **Trusted Publishing** добавить политику GitHub: **Repository Owner = `ivmu5`**, **Repository = `Laveyana.Security`**, **Workflow File = `publish-nuget.yml`**, **Environment = `nuget-release`**. Указывается только имя workflow-файла без пути. Политика должна относиться к NuGet-аккаунту владельца шести пакетов.
2. На GitHub открыть **Settings → Environments**, создать `nuget-release`, включить **Required reviewers** и по возможности ограничить развёртывание релизными тегами. Без защиты дополнительным подтверждением выпуск считается после создания GitHub Release и прохождения проверок.
3. В **Settings → Secrets and variables → Actions → Variables** создать `NUGET_USERNAME`: **логин NuGet.org**, не e-mail. Можно задать и одноимённую переменную окружения GitHub Environment. **Постоянный API Key в GitHub не нужен.**
4. Перед первым выпуском проверить доступность/владение всеми шестью NuGet Package ID. Trusted Publishing не резервирует чужие ID.
5. Проверить PR с конфигурацией и объединить после успешного CI. Упаковка всех шести пакетов будет проверяться обязательным CI на Windows и Linux.

## Публикация новой версии

1. Изменить `LaveyanaVersion` в `Directory.Build.props` обычным PR; получить зелёный CI и объединить.
2. В **GitHub → Releases → Draft a new release** создать тег `v<ВЕРСИЯ>` на коммите, уже включённом в `master`. Для alpha/beta отметить **Pre-release** и нажать Publish.
3. Открыть **Actions → Publish NuGet**. Задание `prepare` выполнит сборку/тесты/упаковку шести пакетов. После подтверждения GitHub Environment `nuget-release` задание `publish` применит Trusted Publishing/OIDC и опубликует те же пакеты.
4. Проверить появление всех шести пакетов на NuGet.org. Индексация может занять некоторое время. Если загрузилась только часть пакетов, прежде чем повторить запуск, проверить состояние каждого. `--skip-duplicate` позволяет повторить загрузку, но не доказывает идентичность содержимого.

**Не пытаться заменить уже опубликованную версию**: для исправления выпускается новая версия. Автоматическая публикация не закрывает SA-03/SA-04/SA-08.

Официальная документация: https://learn.microsoft.com/en-us/nuget/nuget-org/trusted-publishing
