# История изменений

[English](CHANGELOG.md) | **Русский**

Этот журнал фиксирует **неопубликованные этапы разработки**, а не production-релизы или успешную приёмку безопасности. Текущая версия в `Directory.Build.props`: `1.2610.0-alpha.1`. Наличие файла не означает публикацию пакета, гарантию совместимости или выпуск релизного тега.

## Не выпущено — закрытие инфраструктурного этапа H01 (2026-10-16)

- **H01 закрыт (только сборка, CI и защита репозитория):** успешные обязательные проверки, защищённая `master`, три объединённых Pull Request и успешная ручная расширенная регрессия на Windows/Ubuntu. См. [итог H01](docs/hardening/H01-Setup.ru.md).
- **Phase 27 остаётся открытым / production NO-GO:** SA-02, SA-03, SA-04, SA-05 и SA-08 требуют целевых исправлений, тестирования и security review. Закрытие H01 изменяет только документацию, не криптографическое поведение.

## Не выпущено — H01: расширенные регрессионные проверки (2026-10-16)

- Устранены повторные проверки `Verify` в рабочих ветках с открытым Pull Request: каждый PR проверяется один раз, `master` проверяется после слияния. Названия трёх обязательных проверок не изменились.
- Добавлен отдельный workflow расширенных регрессионных проверок с запуском по расписанию и вручную: пять последовательных полных NUnit-прогонов на каждой ОС, проверка TRX и платформенных тестов для каждого повтора, locked restore, Release-сборка, хранение отчётов 14 дней и ограничение времени задания. Существующие обязательные проверки `Verify` не изменены.
- Периодичность расширенных регрессионных проверок изменена с ежедневной на **1-е число каждого месяца в 02:17 UTC** с сохранением ручного запуска. В интерфейсе GitHub workflow называется `Extended Regression` (имя файла `nightly.yml` сохранено).
- [Первый ручной запуск](https://github.com/ivmu5/Laveyana.Security/actions/runs/38908695165) на `master` успешно прошёл на Windows и Ubuntu 16 октября 2026 года. Дополнительные регрессионные проверки **не** означают завершения security-приёмки или закрытия замечаний Phase 27.

## Не выпущено — H01: исправления диагностик сборки (2026-10-16)

**Обновление H01 (16 октября 2026 года):** Workflow `Verify` успешно прошёл на двух CI-платформах: `Source & docs`, `Build & NUnit (ubuntu-latest)` и `Build & NUnit (windows-latest)`. Зафиксированы NuGet lock-файлы; исправлены различия Windows ACL для владельца токена процесса, обёртка Linux native-descriptor и зависимость Linux-теста от `umask`. Включён `Protect master`: обязательны Pull Request и три проверки. Это завершает первичную настройку сборки/CI, **но не** Phase 27 security acceptance.

Исторические записи ниже отражают уровень проверки в момент выполнения изменений. Прежние упоминания неподтверждённой сборки не отменяют новую успешную CI-проверку и не означают production-приёмку.

- Исправлены `CS0618` (NUnit), `CS9174` (`ReadOnlyMemory<byte>`), предупреждения платформенного анализатора `CA1416` для Windows-only тестов.
- Устранены `CS1591` тестовых сборок за счёт выключения XML-документации **только** в тестовых проектах; документирование публичного API библиотеки сохранено.
- Сохранены NuGet lock-файлы; `.vs`, `bin` и `obj` исключены из архива. На данном этапе компиляция и NUnit ещё не были подтверждены (позднее подтверждены H01 CI).

## Не выпущено — H01: исправления компиляции (2026-10-12)

- Исправлены 52 нарушения правила фигурных скобок, добавлены 46 XML-описаний значений публичных `enum`.
- Разделены верхнеуровневые типы по самостоятельным файлам без изменения публичных сигнатур; устраняются первичные причины IDE0011 и CS1591, а каскад CS0006 требует повторной компиляции.
- Добавлена автоматическая проверка `tools/verify_api_layout.py` в CI и [отчёт по исправлениям](docs/hardening/H01-CompilationRepair.ru.md).
- **Компиляция и NUnit не подтверждены; результаты Phase 27 и production NO-GO остаются в силе.**

## Не выпущено — Phase 27 (частичная проверка, 2026-10-10)

- Выполнен статический security review семи проектов, подготовлен [отчёт с приоритетами](docs/audit/Laveyana.Security.Phase27.SecurityAudit.ru.md).
- Изолированы mutable AAD для AES-GCM и mutable сообщения для цифровой подписи до первого асинхронного ожидания; временные буферы очищаются.
- Добавлены тесты изменения входных буферов при ожидании I/O и детерминированные мутации форматов payload.
- **Phase 27 и production gate не закрыты:** сборка, NUnit и Windows/Linux security-тесты пока не выполнены; остаются Windows TOCTOU, rollback и nonce lifetime.

## Не выпущено — Phase 26 (2026-10-10)

- README, спецификация, архитектура и Roadmap сверены с исходниками Phase 25.
- Добавлена двуязычная таблица возможностей и статусов с явным перечислением **неподтверждённых** проверок сборки, тестов и безопасности.
- HPKE и потоковое AEAD обозначены как отложенные, FileSystem — как экспериментальный, постоянное асимметричное хранилище и secret backend — как незавершённые.
- Уточнены намеренные пропуски номеров Decision Log; исторические решения не восстановлены фиктивно и не перенумерованы.
- Добавлены автоматическая проверка документации и её запуск в CI. На Phase 26 криптографическое поведение не изменялось.
